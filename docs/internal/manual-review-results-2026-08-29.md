# Manual review evidence — 2026-08-29

This note records the read-only audit of the two screen recordings and the
local review folder supplied for this checkpoint. The original audio and lyric
files were not edited, copied into the repository, or uploaded.

## Screen-recording observations

The recordings are H.264/AAC MP4 files (1920×1020, 30 fps): the first is
47.13 seconds and the second is 60.27 seconds.

- The timeline rows visibly accept values such as `59:01.000` and `46:08.000`.
  Those values are syntactically valid long timestamps but are outside a
  roughly three-minute song, so the editor gave no useful feedback.
- The Go field visibly receives `1:54:55` and `00:00:000`. The old parser treated
  three colon-separated parts as hours/minutes/seconds, while the intended
  editor form is often minutes/seconds/milliseconds. This explains the report
  that Go and manual numerical entry did not behave as expected.
- No toast is visible in the captured invalid-entry states. The code already
  had a toast component, but invalid timestamp paths only wrote to the activity
  log, so the user-facing feedback was missing.
- The waveform itself shows a moving playhead and a time tooltip. The timeline
  scrollbar is present; clicking a lyric row remains the intended way to seek.

The exact line text is preserved in every compared pair. The timestamps are
not preserved because these outputs were generated by **Initial timing**. This
is expected for the current energy baseline, but the measured deltas show that
it is not yet an accurate automatic aligner. For example, the first Adbhutam
line changes from 38.910 s to 20.400 s; the first APT line changes from 0.240 s
to 6.950 s. The user's manually verified references remain the correct
evaluation target.

## Why Initial timing is instant

The button currently performs a lightweight, deterministic preview: waveform
loading has already computed a 700-bin RMS energy profile, and the button
distributes lyric lines across those bins. It does **not** run MFCC extraction,
DTW, vocal separation, lyric-to-audio comparison, or a cross-check against a
reference LRC. Therefore it should complete in milliseconds for a normal song.
The research engines are isolated reusable modules and CLI experiments; they
are not yet wired into this button. A future production pass should run the
selected engine asynchronously, show progress, and report confidence/review
warnings before export.

## Changes made after this audit

- Added strict, reusable parsing for `mm:ss.mmm`, `mm:ss:mmm`,
  `hh:mm:ss.mmm`, and decimal seconds.
- Added visible toasts for invalid/out-of-range manual times and Go-to-time
  input; Enter in the Go field now performs the same action as Go.
- Added a delete-line icon while keeping clear-timestamp separate.
- Added remove-audio and remove-lyrics controls with cleanup of in-memory
  waveform/timeline state.
- Added parser tests and kept the feature isolated in `src/time-utils.js`.
